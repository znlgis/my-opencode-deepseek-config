# hybrid：素材打底 + 小面积叠加

> 一句话：**hybrid 不是只有"按段拼接"一种做法**。素材本身就是画面时，自绘只该做
> "必要的那一点信息"（一行对照、一个标注、一个角标），按时间窗叠上去即可。
> 本文给出三种形态的取舍、自绘占比预算、matchstyle 的适用边界，以及实测踩过的坑。

## 0. 先选形态（这一步选错，后面全白做）

> **技能默认形态 = 3**（代码默认同此：`intake.py --hybrid-form {3,1}` 缺省 3，形态会落盘进
> `intake.json` 的 `hybridForm`，`--finalize` 打印「形态: 3」与 compose 命令）；**形态 1 需显式 `--hybrid-form 1`**，
> 不显式选择就永远走不到按段拼接。

| # | 形态 | 做法 | 自绘占比 | 什么时候用 |
|---|---|---|---|---|
| 1 | **按段拼接** | 素材段 `footage.py` + 图文段 `render.py`，最后 `concat` | 30~90% | 图文段本身就是完整叙事（数据、原理、流程），素材只是点缀 |
| 2 | **整屏卡片覆盖** | 在素材上盖满屏卡片 | 70~100% | **基本不该用**：素材被遮掉，等于没用素材（实测中试过，观感是"两部片拼一起"） |
| 3 | **素材打底 + 小面积叠加** | `compose.py`：素材就是画面，按时间窗叠小元素 | **≤15%** | 纪实/考据/解说类：画面靠素材立住，只需要少量精确信息 |

判断顺序（推荐从 3 开始往回想）：
1. 把自绘全去掉，只留素材 + 旁白，这片还成立吗？**成立 → 用形态 3**（连 15% 都不用给）
2. 不成立，是因为缺"对比/数据/流程"这类**结构信息**吗？是 → 形态 1（图文段独立成段）
3. 只有个别句子需要补一个数字/标签 → 回到形态 3，只叠那几句

> **为什么默认推荐 3**：实测一部 186 秒的历史对照片，第一版 88% 时长是代码画的整屏卡片，
> 被判定"割裂"；改成素材打底 + 18 条小叠加后，画面统一感立刻成立，且工作量更低
> （不用为每张卡调版式、字号、对比度）。

## 1. 自绘占比预算（形态 3 的量化判据）

| 维度 | 建议上限 | 超了会怎样 |
|---|---|---|
| 画面面积 | **≤15%** | 超过约 20% 就开始遮素材主体，观众注意力从"看画面"变成"读字" |
| 每句元素数 | **≤1 个** | 一行对照 + 一个角标 + 一个进度条同时出现 = 回到整屏卡片 |
| 覆盖句数 | **≤ 句数的 80%** | 全覆盖等于整片都在叠层；留几段纯素材让观众喘气 |
| 单元素停留 | 绑到该句旁白的起止 | 用固定秒数会随配音变长变短而错位 |

达不到这些上限就该问："这个信息能不能只靠**旁白 + 字幕**说清楚？"
能 → **不画**。这是形态 3 最重要的一条。

> 上表是**设计目标**（人照着做）；`compose.py` 另有一套**机器兜底**的叠加预算审计（面积 warn **20%** / fail 30%，常量 `OVL_AREA_WARN/FAIL`，见下节）。
> 两者不是一回事：目标是"尽量小"，审计是"超过这条线就不是叠加了"。

## 2. 工具：`compose.py`

```bash
# 0) 素材线先出到 cut/mix（compose 读 cut.json 与 mix.wav）
python footage.py --footage footage.json --work work --stage all   # 或分阶段跑

# 1) 写 overlay.json（见下）
# 2) 合成（内部强制帧对齐核对 + 两遍 loudnorm）
python compose.py --footage footage.json --overlay overlay.json --work work --out out/film.mp4

# 分阶段（可断点重跑）
python compose.py ... --stage overlay    # 只算时间窗，打印清单
python compose.py ... --stage silent     # 拼底片 + 核对帧数
python compose.py ... --stage audio      # mix.wav -> audio_norm.wav
python compose.py ... --stage compose    # 叠层 + 烧字幕 + 封装
python compose.py ... --stage qa         # 帧级深检（自动传 --shots 切点）
```

### overlay.json 契约

```jsonc
{
  "canvas": [1920, 1080],
  "subtitle": "sub.ass",          // 相对 work/；"" 或缺省 = 不烧字幕
  "layers": [
    {
      "id": "s04",                 // 日志/失败定位用
      "png": "chips/s04.png",      // 相对 --root（默认工程根）
      "bind": "line:s04",          // 时间窗 = timeline 里 s04 这句的 start/end
      "x": "(W-w)/2", "y": 692,    // ffmpeg overlay 表达式；W/w=主/叠加宽
      "fade": 0.18                 // 秒；0 = 硬开关
    },
    { "id": "corner", "png": "chips/logo.png", "at": 12.0, "dur": 4.0,
      "x": "W-w-48", "y": 48 }
  ]
}
```

| 字段 | 必填 | 说明 |
|---|---|---|
| `png` | 是 | 透明 PNG。**同一尺寸**复用最省（换图不换位置） |
| `bind` | 与 `at` 二选一 | `"line:<id>"`：绑到该句旁白起止（改台词自动跟着走，推荐） |
| `at` / `dur` | 与 `bind` 二选一 | 绝对秒；只给 `at` 时默认挂到下一句起点 |
| `until` | 否 | `"next"`：把窗口延长到下一句起点（跨句对照用） |
| `x` / `y` | 否 | 默认居中 / 底部 120px；支持 `(W-w)/2`、`W-w-48` |
| `fade` | 否 | 秒。建议 0.15~0.25：硬开关在暗底上会"啪"一下 |
| `pad_start` / `pad_end` | 否 | 时间窗外扩（负数收缩），用于对齐画面动作 |

**时间窗红线**：元素必须在"这句话没说完"之前消失。绑 `line:` 时窗口默认就是
该句的 `start~end`；如果你手动调 `pad_end` 让它延续到下一句，观众会同时读到两件事。

### 叠加预算审计（`compose.py` 自动拦，落盘 `work/overlay_audit.json`）

`compose.py` 在**叠之前**先用 `layer_coverage()` 量每层 PNG 的不透明像素占比（alpha ≥32 才算覆盖），
再由 `audit_overlay()` 判四条：

| 判据 | fail 线 | warn 线 | 说明 |
|---|---|---|---|
| 单层覆盖面积 | **≥30%** | ≥20% | 盖住三成画面就不是"叠加"，是整屏卡片 |
| 每句叠加层数 | **≥3 层** | — | 一行对照 + 角标 + 进度条同时出现 = 回到卡片；每句只留 1 个信息元素 |
| 被叠加覆盖的句数 | **≥95%** | ≥80% | 全片都在叠，素材成了背景板 |
| 时长加权覆盖 | — | **≥60%** | 素材画面基本没露过；留几段纯素材让观众喘气 |

- 任一条 fail 直接 `SystemExit`；确实需要（信息密集的对照段）加 `--allow-overlay-budget` 放行，
  **但 `work/overlay_audit.json` 里仍记 error**——放行不等于通过。
- **封面/章节层必须显式声明 `"role": "cover"`**：开场与章节转场各盖一张是形态 3 的正常表达，
  但**最多 3 层、面积 ≤65%**；不写 `role` 就按普通层判（30% 就 fail）。`role` 缺省是 `chip`。
- 没装 Pillow 时量不出面积，审计记 `no_pil` 并打 warning（本次预算检查未执行，**不是通过**）。

## 3. 素材治理四配方

形态 3 的所有问题都在素材本身，逐条给配方（都实测过）：

| 症状 | 根因 | 配方 |
|---|---|---|
| 竖版图铺 16:9 出大片黑边 | 等比放进画布 | **模糊铺底**：背景=原图拉伸铺满 + 强高斯模糊 + 压暗到 0.44；前景=清晰原图，高占 88% |
| 长卷取景单调 | 整幅塞进 16:9 | 按 **横向位置窗口** 取多个 16:9 局部（`x0 = (W-cw)*p`），同一张画能出 4~6 个不同镜头 |
| 实景照片和古画色温不搭 | 数码蓝绿 vs 绢本褐金 | **统一色温**：`colorchannelmixer` 强去饱和 + `curves` 压蓝通道；古画只做轻 `eq` |
| 画面上有馆藏编号/扫描色卡/水印 | 扫描件自带 | **裁或补**：优先裁出画外；裁不掉用邻域中位色软边填补（模糊会留轮廓） |
| 素材慢速推移一格一格跳 | 1× 光栅上 1px 台阶 | **超采样**：在 4K 母图上 `zoompan`，直接输出 1080p（1 输入像素 = 0.5 输出像素） |

### 素材时长预算

| 素材量 | 够撑多长 | 复用策略 |
|---|---|---|
| 8~10 张静图 | **150~200 秒** | 每张出 2~3 个取景窗口；单张片内复用 ≤2 次 |
| 30 秒视频素材 | 90~120 秒 | 按内容分段取 `at`，同一段不重复 |

> 实测：9 张公有领域图 + 4 个取景窗口撑 186 秒，千里江山图复用了 4 次（不同窗口）。
> 复用是常态，但**同一取景连续出现两次**会被看出来——所以要多切窗口，不是多找图。

## 4. matchstyle 的适用边界（重要）

`matchstyle.py` 的规则是"素材不动，让图文段向素材看齐"。但它有一个**前提**：
图文段还占相当比例（形态 1）。形态 3 里图文段本来就只有 15%，套不套调色差别很小，
**却有可能把整套设计意图改掉**。

判据（`matchstyle.py` 现在会自己警告，`day_night_conflict` 字段可机读）：

| 素材 luma | 设计底色 | 结论 |
|---|---|---|
| ≥0.35（亮） | 任意 | 正常套用 |
| <0.35（暗） | 暗底 | 正常套用（同族） |
| <0.35（暗） | **亮底** | **警告**：套了之后图文段变近黑，与"明亮"设计意图相反 |

出现警告时的处理顺序（代价从低到高）：
1. **改成形态 3**（低自绘占比 → 配色几乎不影响观感，问题自动消失）
2. 不套 `--apply`，素材段与图文段用**暗场过渡**衔接（0.9 秒淡出淡入；用叠化会重影）
3. 接受暗调，但**先确认需求方是否同意**——这是改需求，不是调色

## 5. 实测踩过的坑（按代价排序）

| # | 坑 | 表现 | 修法 |
|---|---|---|---|
| 1 | **逐镜按秒切 → 累计帧取整误差** | 24 镜累积 0.469s，越到后段字幕/叠加层越落后画面；还可能被帧级质检误报成"单帧闪烁" | `cut_shots` 已改为按累计帧切；`compose.py` 出片前核对 `Σframes == round(total*fps)` |
| 2 | **绕过 assemble 手写合成 → 漏 loudnorm** | 成片 -25.6 LUFS（目标 -16），容器和帧级门禁**都查不出来** | 用 `compose.py`（内部强制两遍 loudnorm），别自己拼 ffmpeg |
| 3 | **真峰压线** | loudnorm 目标 TP=-1.5 → AAC 后实测 -1.0 dBTP（阈值 -1.0） | 默认已改 -2.2；AAC 会抬高真峰 0.5~1.1 dB |
| 4 | **硬切被误判闪烁** | 素材线是硬切，二阶差分在切点必然尖峰 | `qa_frames.py --shots` 传切点，`compose.py --stage qa` 会自动传 |
| 5 | **相对路径遇上 cwd 切换** | 烧字幕时要 `cd` 到 ass 目录，相对路径全失效（`No such file`） | 所有输入先 `resolve()` 成绝对路径 |
| 6 | **GBK 控制台** | 打印中文/子进程回显抛 `UnicodeEncodeError` | `sys.stdout.reconfigure(encoding="utf-8")`；子进程 `encoding="utf-8"` |
| 7 | **叠化转场出重影** | 素材段与卡片结构不同，`xfade` 会把两者同时显影 | 用**暗场过渡**（每侧 0.9 秒淡出淡入）；0.22 秒太短会被判单帧闪烁 |

## 6. 交付前自查清单

1. `compose.py --stage qa` 通过（闪烁 0 / 空窗 0）
2. 响度 -16 ±1 LUFS / 真峰 ≤ -1.0 dBTP（`compose.py` 已保证，仍要**实测确认**）
3. 抽 6~9 帧**亲眼看**：叠加层有没有压住画面主体、有没有和字幕打架、有没有跨句残留
4. 自绘占比核对：面积 ≤15%、每句 ≤1 元素、覆盖句数 ≤80%
5. 素材复用检查：同一取景是否连续出现两次
6. 素材里的非内容元素（馆藏号/色卡/水印）是否已治理
